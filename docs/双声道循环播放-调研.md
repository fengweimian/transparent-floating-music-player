# 「双声道循环播放」调研

> 调研日期：2026-10-05 ｜ 基于当前版本 v3.7.0 ｜ **本文只做调研，未改动任何源码**

---

## 一、一句话结论

**技术上完全可行，已实测通过。** 但「双声道循环播放」至少对应 **4 种完全不同的效果**，实现成本从「半天」到「要动双播放内核」不等，得先确认要哪一种。

---

## 二、先看现在的音频架构（决定改造范围）

| 模板 | 播放内核 | 是否已有 Web Audio 图 |
|---|---|---|
| classic（经典） | `player.js` → `new Audio()` | ❌ 直通输出 |
| new（新版 template2） | `new Audio()` | ✅ **有**（`createMediaElementSource → Analyser → destination`，用于频谱） |
| v3（歌词剧场 template3） | `new Audio()` | ❌ 直通输出 |
| mv（MV 台 template4） | `new Audio()` + `<video>` 出 MV 原声 | ❌ 直通输出 |

已具备的两块地基：

1. **跨域不是问题**。主进程对 `resourceType === 'media'` 注入 `Access-Control-Allow-Origin: *`，所有 `<audio>` 显式 `crossOrigin="anonymous"`。网易云 / QQ / 酷狗 CDN 的歌曲都能进 Web Audio 图而**不被静音**（这正是 v3.6.0 修好频谱恒 0 的同一套机制）。
2. **声道路由是 Web Audio 原生能力**，无需第三方库、无额外依赖、无性能负担（几个节点的开销可忽略）。

⚠️ **关键含义**：做声道效果＝要给**所有模板**接一套统一的音频引擎（classic / v3 / mv 现在都没有图，且 MV 的原声走 `<video>`）。**只改一处是不行的**，这是主要工作量所在。

## 三、「双声道循环播放」的可能含义

| # | 效果 | 听感 | 典型用途 | 实现 | 成本 |
|---|---|---|---|---|---|
| **A** | **左右交替轮播**<br>左响 N 秒 → 右响 N 秒 → 循环 | 声音忽左忽右地「跳」 | 耳机单边测试、听力训练、左右平衡校准 | `ChannelSplitter → 2×Gain → ChannelMerger`，定时器轮流开关增益 | 低 |
| **B** | **8D 环绕**<br>声音在左右之间平滑来回流动 | 脑袋里绕圈，很上头 | 抖音那种「8D 环绕音效」 | `StereoPannerNode` 的 `pan` 接一个 0.1~0.5Hz 的 LFO（`OscillatorNode`）来回扫 | **最低** |
| **C** | **左右互换 / 单边独听** | 声场翻转，或只剩一边 | 测试耳机接反、只听某一声道 | Splitter/Merger 交叉接线，或复制单边到两边 | 极低 |
| **D** | **双声道分流**<br>左耳一首歌、右耳另一首歌，各自循环 | 左右耳听不同内容 | 语言学习、双流对比、整活 | 需要**两个独立播放内核 + 双队列**，各路 Splitter 取一路再合并 | **最高** |

> 📌 补充：如果指的是「**单曲循环**」，这个功能**现在已经有了**（播放模式里的「单曲循环」，`repeatOne`），不需要新做。

## 四、实测验证（OfflineAudioContext，真实渲染取数）

测试信号：立体声 4 秒，左声道 440Hz × 0.5，右声道 880Hz × 0.2。按每 1 秒统计 L/R 的 RMS 能量：

| 路线 | 0–1s (L,R) | 1–2s (L,R) | 2–3s (L,R) | 3–4s (L,R) | 全程 L / R |
|---|---|---|---|---|---|
| 直通基线 | 0.3536, 0.1414 | 同上 | 同上 | 同上 | 0.3536 / 0.1414 |
| **A 左右交替** | **0.3536, 0.0082** | **0.0204, 0.1414** | **0.3536, 0.0082** | **0.0204, 0.1414** | 0.2504 / 0.1002 |
| **B 8D 环绕** | 0.2085, **0.3186** | 0.2085, 0.3186 | **0.3715**, 0.0834 | 0.3715, 0.0834 | 0.3013 / 0.2329 |
| **C 声道互换** | **0.1414, 0.3536** | 同上 | 同上 | 同上 | 0.1414 / 0.3536 |
| C 单边独听(左) | 0.3536, **0.3536** | 同上 | 同上 | 同上 | 0.3536 / 0.3536 |

**读数**：
- **A**：每一秒只有一边有能量，另一边降到 ~0.008（残留是 10ms 防爆音斜坡）→ 交替确实生效。
- **B**：前 2 秒偏右（R 0.319 > L 0.209），后 2 秒偏左（L 0.372 > R 0.083）→ 声音在左右之间**流动**，正是「循环」的听感。
- **C**：L/R 能量对调 → 交叉路由接对了。
- C 单边独听：左声道被复制到两边（0.3536 / 0.3536）→ 单边铺满立体声。

## 五、真正会踩的坑（落地时必看）

1. **一个 `<audio>`/`<video>` 只能 `createMediaElementSource()` 一次**，重复调用抛 `InvalidStateError`。所以要做成**统一音频引擎**，template2 已有的图要复用而不是重建。
2. **一旦接入 Web Audio，音频就永远走图了**，不能「完全旁路回原始直通」。等价做法是给一条 gain=1 的普通通路当直通模式。听感无差（Chromium 本来就会重采样到 48kHz），代价是不再是 bit-perfect —— 对本项目无实际影响。
3. **单声道音源要 up-mix**。部分老歌是单声道，`ChannelSplitter(2)` 的第 2 路会全静音，交替 / 环绕效果会退化成「只有一边响」。
4. **切换必须加斜坡（ramp）**。硬切会有明显「啪」的爆音。
5. **AudioContext 要用户手势才能 resume**。本项目已设 `autoplay-policy: no-user-gesture-required`，但首次播放时仍需确保 context 已 resume。
6. **必须默认关闭**。否则普通用户一开播放器发现「只有一边响」会以为坏了。
7. **MV 台要不要一起处理**：MV 原声走 `<video>`（MV 播放时 `<audio>` 是暂停的），要支持就得对 video 也建图。
8. **切模板会重建图**（页面整页重载），状态需重新应用。

## 六、建议

- **想要「炫」** → 选 **B 8D 环绕**：成本最低（一个 LFO 节点）、最贴合「循环流动」的字面意思、听歌不难受，还能当卖点。
- **想要「实用/测试」** → 选 **A 左右交替**：实现也简单，但长时间听会难受，建议做成「限时试听」或可调周期。
- **C 声道互换** → 顺手就能带上（同一套节点，多一个开关）。
- **D 双声道分流** → 工程量最大，建议如有需要单独排一期。
