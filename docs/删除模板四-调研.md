## 3. 需要你拍板的两个问题

### 问题 1：MV 解析链路要不要一起删？

删掉模板四后，整条 MV 功能**没有任何调用方**，变成死代码：

| 位置 | 规模 | 内容 |
|---|---|---|
| `scripts/main.original.js:3089-3350` | **约 260 行** | `probeVideoUrl`、`mvNeteaseMeta`、`mvNeteaseByMvid`、`mvQqByVid`、`mvKugouByHash`、`mvFindNetease`、`mvFindQq`、`mvFindKugou`、`music:mv` IPC |
| `preload.js:60` | 1 行 | `mv: (id, server, name, artist) => ipcRenderer.invoke("music:mv", …)` |
| `renderer/shared/api.js:218-240` | 约 22 行 | `mvResolve()` 包装 |

**选项 A：一起删**（推荐）
- 主进程少 260 行，`main.jsc` 体积和加载都轻一点
- 缺点：以后想恢复 MV 功能得从 git 历史里翻

**选项 B：保留**
- 只是不建模版四，MV 接口留着（死代码但不影响运行）
- 缺点：以后维护容易被误以为是活的入口

### 问题 2：版本号怎么涨？

| 选择 | 依据 |
|---|---|
| **3.11.0**（minor） | 项目规范「功能→minor」，删掉一个模板属于功能面变更（推荐） |
| 3.10.7（patch） | 若你更看重"只是精简"，按 patch 也能说得通 |

## 4. 风险与兜底（都已确认安全）

| 风险 | 结论 |
|---|---|
| 用户当前设置是 `mv`，删完后启动白屏？ | ✅ 不会。`app:switch-template` 的三元链最后兜底 `: "classic"`；但 `templatePath()` 的分支必须同步删，否则残留一个指向已删文件的路径 |
| 打包时还会不会带上 template4？ | ✅ 不会。`package.json` 的 `files` 是 `renderer/**/*` 通配，删目录即生效，无需改配置 |
| 其他模板是否依赖模板四的共享改动？ | ✅ 不依赖。t4 只是引用 `../shared/*.js`，没有反向修改共享层 |
| 桌面歌词 / 主窗口 / 托盘 是否受影响？ | ✅ 不受影响，那些都走主进程，与模板路径无关 |
| 旧安装包/旧版用户 | 无影响，本次是删源码不涉及升级逻辑 |
