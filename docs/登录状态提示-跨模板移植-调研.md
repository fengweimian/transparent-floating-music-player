# 通知卡片（toast）跨模板移植 · 调研

> 调研时间：2026-11-07 · 版本 v3.10.6 · **仅调研，未改代码**
> 需求：把模板一（classic）那个卡片搬到其他模板
>
> ⚠️ **范围更正**：这套卡片不只服务「登录状态」——classic 里同一个 `showToast()`
> 覆盖 **29 个场景**（下载进度、登录结果、歌单操作、音量、队列操作、播放错误……），
> 详见第 1.5 节。移植要按"通知体系"而不是"一个提示"来规划。

## 1. 你截图那张卡片的来历

```js
setTimeout(async () => {

  const expired = [];

  }
}, 3000);
```

## 2. 卡片的具体规格（`renderer/style.css:1592-1660`）

**结构**（两行，标题 + 副文本）：

```html
<div class="toast-item toast-info toast-clickable">
  <span class="toast-title">登录状态</span>
  <span class="toast-sub">网易云 登录已过期，点击打开设置重新登录</span>
</div>
```

| 项 | 值 |
|---|---|
| 位置 | 右上角固定 `top:18px right:18px`，纵向堆叠，最多 3 条 |
| 卡片 | `rgba(panel-bg, 0.92)` 深色底 + 1px 12% 白边 + 10px 圆角 + `backdrop-filter: blur(12px)` + 大阴影 |
| 左侧色条 | `border-left: 4px solid` 按类型着色：success `#34c759` / error `#ff453a` / **info `#8e8e93`（截图里那条灰竖边就是它）** |
| 标题 | 600 粗体，info 时 `#9ea5b8` |
| 副文本 | 12px，`rgba(255,255,255,0.75)` 左右 |
| 动画 | 进场 `toast-in` 0.25s，退场 `translateX(24px)` + 淡出 |
| **停留** | **传了 clickPath 就不自动消失**（常驻到你点它），没传则 4 秒消失 |
| 交互 | 可点击时 `cursor:pointer`，hover 背景变亮 `rgba(38,42,66,.95)` |

点击行为有两种（`app.js:602-616`）：

| clickPath | 行为 |
|---|---|
| `"settings"` | `window.openSettingsPanel()` 打开设置窗口（含账号区） |
| 具体文件路径 | `shell.showItemInFolder(path)`（下载完成时用） |

同一个 `showToast` 还被复用在：登录成功、音效切换、静音提示、下载中/完成/失败等 10 来处。

## 3. 其他模板现状：三层差距 + 一个隐藏 bug

四个新模板走的是另一套轻提示 `showFeedback(text, sticky)`：

```js
function showFeedback(text, sticky) {
  const tip = $("feedback-tip");
  tip.textContent = text;          // ← 纯文本，撑不起标题+正文
  tip.style.opacity = "1";
  clearTimeout(tipTimer);
  if (sticky === true) return;     // 只有显式传 true 才常驻
  tipTimer = setTimeout(() => { tip.style.opacity = "0"; }, 1800);   // ← 1.8 秒就消失
}
```

登录过期的调用（t2:2863 / t3:2737 / t4:3087 / t5 同构）是：

```js
showFeedback(expired.join("、") + " 登录已过期，点击菜单「我的音乐」重新登录");   // ← 没有 sticky
```

### 差距对照

| 能力 | classic | t2 | t3 / t4 / t5 |
|---|---|---|---|
| 双行（标题 + 正文） | ✅ | ❌ 单行 | ❌ 单行 |
| 停留时长 | ✅ 常驻（直到点击） | ❌ 1.8 秒 | ❌ 1.8 秒 |
| 点击跳转设置/账号 | ✅ | ❌ | ❌ |
| 卡片样式 | ✅ 深色卡片 + 左侧色条 | ✅ 居中胶囊（有样式） | ❌ **完全无样式** |

### 🐛 顺带查出的 bug：t3 / t4 / t5 的提示条根本没有 CSS

三个模板的 CSS 里写的是 `#tip`，但 DOM 元素的 id 是 `feedback-tip`：

| 模板 | CSS 选择器 | 实际元素 id | 是否匹配 |
|---|---|---|---|
| t2 | `#feedback-tip` | `feedback-tip` | ✅ |
| t3 | `#tip` | `feedback-tip` | ❌ |
| t4 | `#tip` | `feedback-tip` | ❌ |
| t5 | `#tip` | `feedback-tip` | ❌ |

t5 里那条 `#tip { position:fixed; left:50%; bottom:6vh; … }`（index.html:228）是**死规则**，
没有任何元素叫 `tip`。

后果：这三个模板里**所有** `showFeedback()` 提示（正在获取音频地址 / 已加入队列 / 下载中 /
各种失败原因 / 登录过期）都是**无定位、无背景、无圆角的裸文本**，出现在文档流里，
且因为没有 `transition` 定义，1.8 秒后是"瞬间消失"而不是淡出。

历史追溯：t3 上线（v3.5.8）时就已经是 `feedback-tip` 元素 + `#tip` 样式，一直没对过；
v3.10.3 把提示统一收敛到 `showFeedback()` 之后，受影响的场景才变多。

## 4. 移植方案（三档，按改动量）

### 方案 A：一行改动（只治"看不见"）

给登录过期那处加 `true`：

```js
showFeedback(expired.join("、") + " 登录已过期，点击菜单「我的音乐」重新登录", true);
```

- ✅ 改 4 个文件各 1 个参数
- ❌ 仍是单行、仍不可点、t3/t4/t5 仍无样式

### 方案 B：抽公共 toast 组件（推荐，符合项目 shared/ 架构）

新增 `renderer/shared/toast.js` + `shared/toast.css`：

```js
XFToast.show({ title, message, type: "info"|"success"|"error", onClick, sticky });
```

- 结构/样式直接沿用 classic 的 `.toast-item` 那套（深色卡片 + 左侧色条 + 右上角堆叠）
- 五模板 `<link>` + `<script>` 各加一行；登录过期改用 `XFToast.show({ title:"登录状态", …, onClick })`
- 顺带把 t3/t4/t5 的 `#tip` / `#feedback-tip` 不匹配修掉
- classic 可以保留现有实现不动（避免回归），只让新模板接入新组件
- ⚠️ 需要把"点击后干什么"做成回调注入（classic 是 `openSettingsPanel()`，
  新模板是打开内嵌账号面板，见第 5 节）

### 方案 C：只给登录提示单独加一套（不抽组件）

四个模板各自复制 40 行 CSS + 30 行 JS，只服务登录过期这一处。

- ✅ 完全不动现有 `showFeedback`，风险最低
- ❌ 四份重复代码，后续维护要改四处

## 5. 点击落点映射（各模板不一样，得分别接）

| 模板 | 登录入口在哪 | 点击后应执行 |
|---|---|---|
| classic | 独立设置窗口（`openSettingsPanel()`） | 直接调用即可 |
| t2 / t3 / t4 | 内嵌账号面板（菜单里） | 关闭其它面板 → 打开 `#account-panel` |
| t5 | 菜单「我的音乐」`#menu-account` → `#account-panel` | 同上（t5 的账号面板在 index.html:683） |

所以不能简单复制 classic 的 `clickPath === "settings"` 分支，得改成传回调。

---

## 6. 建议顺序

1. **先修 t3/t4/t5 的 `#tip` → `#feedback-tip` 选择器**（改 1 行 CSS × 3 个文件，收益最大：
   所有操作提示立刻恢复成居中胶囊样式）
2. 登录过期提示加 `true`（常驻）—— 立刻解决"一闪就没"的问题
3. 再上方案 B，把卡片（标题+正文+可点击）做成公共组件
