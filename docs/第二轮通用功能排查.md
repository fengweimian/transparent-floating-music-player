## 1. P0：`prompt()` 抛异常，歌单导入/重命名全废

### 实测

```
点击「导入歌单」按钮（#menu-import）后：
  → 弹窗数 0（没弹出任何对话框）
  → 捕获到：Uncaught Error: prompt() is not supported.
```

单独调用 `window.prompt('测试','默认值')` 直接 `throw`：

```
{"抛异常":"prompt() is not supported."}
```

Electron 从内核层面禁用了 `prompt()`（`alert` / `confirm` 仍然可用，会弹原生框）。

### 受影响代码（四套新模板，同构）

| 文件 | 行 | 功能 |
|---|---|---|
| `template2/app.js` | 2209 | 重命名歌单 |
| `template2/app.js` | 2271 | 导入歌单 → 输入链接 |
| `template2/app.js` | 2285 | 导入歌单 → 输入名称 |
| `template3/app.js` | 2125 / 2187 / 2201 | 同上三处 |
| `template4/app.js` | 2475 / 2537 / 2551 | 同上三处 |
| `template5/app.js` | 2268 / 2330 / 2344 | 同上三处 |

`openImportDialog()`（t5:2329）里 `const url = prompt(...)` **不在 try 内**：

```js
function openImportDialog() {
  const url = prompt("粘贴网易云/QQ音乐歌单链接或歌单ID：…");   // ← 直接抛，整个函数中断
  if (!url) return;
  importPlaylist(url);
}
```

→ 点按钮**没有任何反应**（异常冒到事件处理器，用户看不到提示）。

而名称那一步在 `try` 内，会走到 catch：`导入失败：prompt() is not supported.`

### 对照：classic 是好的

`renderer/app.js` 用的是真实 DOM 输入框，没有 prompt：

```js
const importUrlInput = $("#import-url-input");
const importNameInput = $("#import-name-input");
const renameInput = $("#rename-input");
```

→ 也就是说这是**新模板重写时的回归**，不是全项目都有。

### 影响

- 用户无法导入任何歌单（网易云 / QQ 都不行）
- 用户无法重命名自定义歌单
- README 宣称的「歌单导入：支持网易云、QQ 音乐歌单链接（含 QQ 短链自动展开）」在新模板下不成立

## 2. P1：`downloadFile()` 不校验 HTTP 状态码

```js
function downloadFile(url, destPath, depth = 0) {
  return new Promise((resolve, reject) => {
    const req = lib.get(url, { headers: ... }, (res) => {
      if (res.statusCode >= 300 && res.statusCode < 400 && res.headers.location) { /* 只处理重定向 */ }
      const file = fs.createWriteStream(destPath);
      res.on("data", (chunk) => { ... });
      res.on("end", () => { file.end(); resolve({ size: downloaded }); });   // ← 200/403/404 一律 resolve
    });
    ...
```

**只判断了 3xx**，200 以外的响应（403 地址过期、404 不存在、5xx）都会：
1. 创建目标文件
2. 把错误响应体写进去（0 字节或错误页）
3. **`resolve` 成功**

调用方据此返回 `{ success: true, size: "0.0MB" }`，界面上是"下载完成"。

### 实测后果

`music:download` 下载完成后：

```
AURORA - Cure For Me [002r9FpE35sP].mp3    7,957,150 B   ✅ 完整（= 320k 档位大小）
AURORA - Cure For Me [002r9FpE35sP].lrc        2,057 B   ✅
AURORA - Cure For Me [002r9FpE35sP].jpg            0 B   ❌ 空文件，但接口返回 success
```

音频本身正常，**封面是 0 字节空文件却报成功**。

同类风险：音频地址若在下载时已过期（vkey 有时效），会写 0 字节 mp3 或 HTML 错误页，用户得到一个打不开的"下载完成"文件。

## 3. P1：封面地址全部失效（两个渠道都拿不到）

### QQ：用错 ID

`music:download` 里：

```js
const picRaw = await meting.pic(id, 300);   // id = songmid
```

meting 的 tencent provider 直接把它拼进封面模板：

```js
`https://y.gtimg.cn/music/photo_new/T002R${e}x${e}M000${t}.jpg`
```

但 `T002R300x300M000` 后面要的是**专辑 mid（albummid）**，不是歌曲 mid（songmid）。

实测：

```
https://y.gtimg.cn/music/photo_new/T002R300x300M000002r9FpE35sPuL.jpg
→ HTTP 404 | 0 B
```

正确的专辑 mid 在搜索结果的 `pic` 字段里已带出来（如 `T002R300x300M000002pNm0n06EIlk.jpg`），只是下载流程没用上。

### 网易云：CDN 规则变了

meting 的 netease pic 拼的是老格式：

```
https://p3.music.126.net/{加密ID}/{songId}.jpg?param=300y300
```

实测 3 首（含热门曲）**全部 404**，返回体是 S3 错误 XML：

```xml
<Error><Code>NoSuchKey</Code><Message>object not exist</Message><Resource>yyimgs/...
```

落盘后就是一个 211 字节、扩展名为 `.jpg` 的 XML 文件。

### 结论

README 写的「一键下载 **MP3 + 歌词 + 封面**」，封面这一项**在所有渠道都拿不到**，
而且因为问题 2（不校验状态码），失败还不会提示，用户以为下载成功了。

## 4. P3：`importPlaylist` 内部崩溃

主进程日志：

```
music:importPlaylist failed: Cannot read properties of undefined (reading 'name')
```

触发条件：导入一个不存在的 QQ 歌单链接。

最终返回给界面的是"歌单为空或无法解析"（用户侧表现尚可），但中间抛了一次空指针，
说明解析分支对 `data.v_playlist` / `cdlist` 之类的空值没做保护。属于健壮性问题。

## 6. 修复建议（未实施）

| 优先级 | 修法 |
|---|---|
| P0 | 把四处 `prompt()` 换成页面内自建输入弹层（classic 已有 `#import-url-input` / `#rename-input` 可参照），或临时改用 `window.electronAPI.dialog` 新增一个 `input()` 方法 |
| P1 | `downloadFile()` 在 `res.on('data')` 之前判断 `statusCode !== 200 && !== 206` → `res.resume()` + `reject(new Error('HTTP ' + code))`；失败时删除已创建的空文件 |
| P1 | 封面改用**搜索结果的 `pic` 字段**：`music:download` 增加 `pic` 参数（渲染层 `song.cover` 已有），主进程优先用它，`meting.pic` 只作兜底；同时校验响应 `content-type` 必须是 `image/*` 再落盘 |
| P3 | `importPlaylist` 的 QQ 分支对 `v_playlist` / `songlist` 做空值保护 |
