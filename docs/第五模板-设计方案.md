## 一、定位：它和现有 MV 台（t4）的区别

这是**为什么值得新增第五个模板**的核心论据：

| | t4「MV 台」 | **第五模板「歌词 MV 舞台」** |
|---|---|---|
| 内容来源 | 三源找**官方 MV 视频**（网易云 / QQ / 酷狗） | **歌词本身** |
| 可用率 | ⚠️ **只有少数歌有官方 MV**，命中不到就显示"这首歌没有 MV" | ✅ **每首歌都有歌词** → 每首歌都能有舞台 |
| 形态 | 视频播放器（真视频） | 全屏歌词动画（视觉演出） |
| 失败态 | 空态页 + "重新查找" | 降级为行级扫光，**永不空态** |

**一句话**：t4 是"有 MV 才好看"，第五模板是"没 MV 也好看"。

而 v3.9.0 落地的波点音源把**逐字覆盖率从 2/8 拉到 8/9**——这正是舞台式动画最缺的燃料，时机已经成熟。

## 三、视觉方案：三个候选模式

> Folia 有 13 个模式（fume / lumiere / cadenza / partita / cappella / tilt / diorama / pendolo / sonnet / tempera / monet …）。我们**不追求数量**，先做 1 个做透。

### 模式 A —— 「流光」（推荐先做）

```
┌──────────────────────────────────────┐
│                                      │
│         （封面主色渐变压暗背景）          │
│                                      │
│           遮住你今天新添的伤疤            │  ← 超大号当前行
│           ▓▓▓▓▓▓▓▓░░░░░░░░              │  ← 逐字点亮（复用 --scan-p）
│                ▲                     │  ← 扫描前沿一道竖向光晕（Canvas 层）
│                                      │
│          · 已唱过的行向上淡出漂移 ·        │
│                                      │
│   ──────────●───────────────  1:23   │  ← 极简进度条（可自动隐藏）
└──────────────────────────────────────┘
```

- **复用度最高**：点亮机制就是现有 `--scan-p` + `background-clip:text`，`scanLoop()` 里的前沿公式**原样照搬**
- **增量成本低**：只需再加一层 Canvas 画"光晕 + 粒子"
- **最接近 Folia 招牌观感**（它的 Lumiere 就是光束路线）

### 模式 B —— 「歌词栏」（备选，成本最低）

垂直歌词列（类似 Apple Music / 网易云桌面歌词的舞台化版）：当前行放大 + 逐字填充，其余行**模糊 + 降透明**形成景深，随播放滚动。

- 几乎纯 CSS，**零 Canvas**，风险最低
- 但视觉冲击弱于 A，"MV 感"不足

### 模式 C —— 「群唱气泡」

歌词字从四散飘入、聚合成句（Folia 的 Cappella 路线）。

- 效果最花哨，但**逐字依赖最强**，且实现与调参成本高
- 建议**不进入首版**

### 对比与建议

| 模式 | 复用现有机制 | 新增代码量 | 视觉冲击 | 逐字依赖 | 建议 |
|---|---|---|---|---|---|
| **A 流光** | 高（扫光直接复用） | 中 | **强** | 中 | ✅ **首版做这个** |
| B 歌词栏 | 中 | **低** | 弱 | 低 | 备选 / 第二模式 |
| C 群唱 | 低 | 高 | 强 | **强** | 暂不做 |

## 四、技术选型决策

| 层 | 选型 | 理由 |
|---|---|---|
| 歌词排版 / 点亮 | **DOM + CSS** | 复用现有 `--scan-p` + `background-clip:text`，与 t2/t3/classic 完全一致，**零新机制** |
| 光效 / 粒子 / 背景流动 | **Canvas 2D** | 够用、无依赖、透明窗口 alpha 友好 |
| ~~WebGL（three / pixi）~~ | ❌ **不采用** | ① 违背"零构建 vanilla"契约；② Electron 33 对 Pixi8/three 0.185 兼容性未验证；③ 透明窗口下 GPU 合成与点击穿透是已踩过的坑 |
| 动画驱动 | `requestAnimationFrame` 单循环 | 与现有 `scanLoop()` 同构 |

> ⚠️ **透明窗口注意**：Canvas 与背景必须走 alpha 合成（不要 `fillRect` 铺不透明底），否则会破坏"全透明悬浮"的产品特征。

## 五、数据契约：完全复用，**不需要新歌词管线**

调研文档第 ① 阶段曾建议"补词级 / 逐 grapheme / 翻译独立字段"——**自研模式下这一步可以砍掉**。理由：模式 A/B 都只用到**行级 + 字级**，这正是现有 `buildLines()` 已经产出的。

```js
// 唯一数据入口（与四模板完全一致）
const lines = XFLyrics.buildLines(lyric, qrc || yrc, { timeUnit: "ms" });
// → [{ time: 12345, text: "遮住你今天新添的伤疤",
//      chars: [{ text:"遮", start:12.34, dur:0.16 }, ...] }]
```

### 逐字可用率（决定降级链）

| 音源 | 实测逐字覆盖 |
|---|---|
| **波点**（v3.9.0 新增） | **8/9 首** |
| 网易云 | 2/8 首 |
| QQ | 高（QRC） |
| 酷狗 | **0**（经 meting 解密为纯 LRC） |

### 降级链（必须逐级兜底，**任何情况都不空屏**）

```
有 chars → 逐字点亮（toFixed(2)）      ← 波点/QQ/部分网易云
  ↓ 无
有行级 time → 整行匀速推进（toFixed(1)） ← 酷狗等
  ↓ 无
有曲目信息 → 封面 + 歌名歌手静态展示
  ↓ 无
纯色渐变背景
```

> 判定扫光走的是哪条分支：看 `--scan-p` 的小数位（2 位=逐字 / 1 位=行级）。

## 六、音频驱动（分两版，V1 先上）

| 版本 | 驱动源 | 效果 | 风险 |
|---|---|---|---|
| **V1** | 纯时间（`audio.currentTime`） | 歌词随时间点亮，光效恒定节奏 | **零风险**，首版就用这个 |
| V2 | Web Audio 频谱（`audioBands`） | 光晕/粒子随低音鼓点呼吸 | 需接 Web Audio 图，见下 |

### ⚠️ V2 的硬约束（这是最容易踩的坑）

`HTMLMediaElement` **只能 `createMediaElementSource()` 一次**。本项目 `shared/audio-fx.js`（v3.8.0 双声道音效）已经占用了这个调用，且它明确提供了**只读并联出口**：

```js
// shared/audio-fx.js
//  1) 一个 HTMLMediaElement 只能 createMediaElementSource() 一次，
//     模板已有 Web Audio 图（如新版模板的频谱）必须走 tap()，不要自己再建。
//  master → tap(node) 供频谱等只读节点并联（死端，不影响输出）
```

**所以 V2 必须写 `audioFx.tap(analyser)`，绝不能自己再 `createMediaElementSource`** —— 否则与双声道音效互斥（后者会直接失效）。参考实现：`renderer/template2/app.js` 的 `initSpectrum()`（第 747 行起）。

## 十、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 透明窗口下 Canvas 合成异常 / 破坏全透明 | 🟠 | Canvas 只画带 alpha 的光效，不铺底；先做最小 demo 验证 |
| 全屏 1920×1080 下 rAF + Canvas 掉帧 | 🟠 | DOM 只在**切行时**重建；粒子数量设上限；提供"关闭光效"开关 |
| 逐字覆盖率不足导致大面积走行级 | 🟡 | 降级链已覆盖；且波点源覆盖率 8/9，实际影响小 |
| P3 频谱与双声道音效互斥 | 🟠 | 强制走 `audioFx.tap()`，绝不自己建 source |
| 新增设置入口要改 4 个模板（含命名不一致的经典模板） | 🟡 | P2 集中处理，逐模板核对 |
| 与 Folia 的许可边界 | 🔴 | **只参考视觉语言，一行 Folia/AGPL 代码都不搬** |
