## 三、🟠 P1 · 功能受损 / 数据错误

### 2. `downloadFile()` 不校验 HTTP 状态码

`scripts/main.original.js:3594`。只处理 3xx 重定向，403/404 一律走到 `resolve({size})`，调用方认为下载成功。

**实测**：`music:download` 返回 `success:true`，但封面文件 **0 字节**。

风险：音频地址过期（vkey 有时效）时会"下载成功"得到一个 0 字节 mp3 或 HTML 错误页。

### 3. 封面下载在所有渠道都失效

| 渠道 | 问题 | 实测 |
|---|---|---|
| QQ | `meting.pic(songmid)` 拼出的 URL 位置需要**专辑 mid** | `HTTP 404 / 0 B` |
| 网易云 | meting 老格式 `p3.music.126.net/{加密}/{id}.jpg` 已失效 | **3/3 全部 404**，返回 S3 `NoSuchKey` XML → 落盘成 211 B 的 `.jpg` |

位置：`scripts/main.original.js:3742`（下载流程）。
正确的封面 URL 在搜索结果的 `pic` 字段里（`song.cover` 已有），下载流程没用上。

### 4. 经典模板：取址失败后点播放 → 播上一首

| 项 | 内容 |
|---|---|
| 位置 | `renderer/player.js:287`（`_pauseBeforeFetch` 只 pause 不清 src）、`:305/329/356`（失败直接 return）、`:390`（`playPause` 只看 `if (audio.src)`） |
| 实测 | 《幻听》→ 点酷狗失败歌 → 点播放 → 《幻听》从 4.7s 播到 11.7s |
| 说明 | 因为 `trackchange` 只在成功路径发，主界面标题也停在上一首，所以 UI 与音频"自洽"；但内部 `currentTrack` 已是新歌、`audio.src` 是旧歌，属潜伏状态 |

### 5. 经典模板：取址期间点播放 → 先响 0.3~0.7 秒旧歌

事件序列：`pause(A) → play(A) → setSrc(B) → play(B)`。同一个根因（不清 src）。

### 6. t3 / t5 的提示条没有任何样式

| 模板 | CSS 选择器 | 元素 id | 结果 |
|---|---|---|---|
| t2 | `#feedback-tip` | `feedback-tip` | ✅ |
| t3 | `#tip` | `feedback-tip` | ❌ |
| t5 | `#tip` | `feedback-tip` | ❌ |

t5 的 `#tip { position:fixed; left:50%; bottom:6vh; border-radius:999px; … }`（index.html:228）是死规则。

后果：这两个模板所有 `showFeedback()` 提示（正在获取地址 / 已加入队列 / 下载进度 / 失败原因 / 登录过期）都是**无定位、无背景的裸文字**，且无 transition，1.8 秒后瞬消失。

历史：t3 上线（v3.5.8）起就错，v3.10.3 统一收敛到 `showFeedback()` 后影响面才变大。

## 四、🟡 P2 / ⚪ P3

### 7. `_errSong` 永不重置（t2:569 / t3:555 / t5:561）

同一首歌**第二次**直链失效时，error 监听直接 return → 音频静默卡住、无提示、点播放也不重取。

### 8. error 监听认错了歌（同三处）

```js
const song = curSong();   // 用"当前 UI 的歌"，不是"这个 src 属于谁"
failPlay(song, ...);      // 切歌瞬间的延迟 error 会把新歌停掉
```

守卫只挡了 `!audio.getAttribute("src")`，挡不住"新 src 已就位、旧 error 才到"。

### 9. 移除当前播放曲后，队列非空却提示"请先搜索"

t5 实测：3 首队列 → 播第 2 首 → 移除 → `currentIdx=-1`，音频正确停止；但队列还剩 2 首，点播放提示"请先搜索歌曲或选择音乐文件夹"。

### 10. 两套模板的错误策略不一致

| 场景 | 新模板（t2/t3/t5） | classic |
|---|---|---|
| 直链失效 | `failPlay`：停住 + 提示，不跳歌 | **自动 `next()` 跳下一首**（连续 3 次才停，`player.js:50-68`） |

classic 的自动跳歌可能是"音频变成下一首"的另一来源。

### 11. `music:importPlaylist` 处理无效 QQ 歌单时空指针

日志：`Cannot read properties of undefined (reading 'name')`。用户侧仍看到失败提示，属健壮性问题。
